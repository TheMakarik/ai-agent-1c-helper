# Роли и права

## Назначение

Скилл описывает назначение ролей в конфигурации: какие права можно выдать на объекты метаданных, как устроены пакеты и интерфейс роли, как назначать роли пользователям и как проверять права в коде.

## Ключевые понятия

- Роль — объект метаданных, набор прав на объекты конфигурации; назначается пользователю или профилю группы доступа.
- Права на объект — действия: Чтение, Добавление, Изменение, Удаление, Проведение, Отмена проведения, Интерактивное добавление/изменение/удаление, Ввод по строке, Просмотр, Редактирование, Вывод и другие.
- Пакеты прав — группировка набора прав для удобного назначения; в современных версиях роль хранит права одной таблицей.
- Интерфейс роли — видимость разделов командного интерфейса и отдельных команд для пользователя с этой ролью.
- Ограничения доступа к данным — таблица прав роли, содержащая шаблоны ограничений на уровне записей (RLS).
- Привилегированный режим — выполнение кода в обход проверки прав и RLS.
- Профиль группы доступа (БСП) — набор ролей, назначаемый группе пользователей.

## Как это работает

1. В роли отмечаются объекты и права на действия с ними.
2. В разделе «Интерфейс» задаётся, какие разделы и команды увидит пользователь.
3. В разделе «Ограничения доступа к данным» задаются шаблоны RLS (если нужны).
4. Роль назначается пользователю напрямую или через профиль группы доступа.
5. Платформа проверяет права при обращении пользователя к объектам; в коде проверку выполняют явно.
6. Привилегированный режим включается на время серверных операций: `УстановитьПривилегированныйРежим(Истина)`.

## Пример

```bsl
// Пример: явная проверка прав перед выполнением операции.
Процедура ЗаписатьНоменклатуру(Ссылка) Экспорт
    Если Не ПравоДоступа("Изменение", Метаданные.Справочники.Номенклатура) Тогда
        ВызватьИсключение "Недостаточно прав на изменение номенклатуры";
    КонецЕсли;

    // Привилегированный режим используют для служебных операций,
    // а не для обхода прав в пользовательских сценариях.
    УстановитьПривилегированныйРежим(Истина);
    Попытка
        Объект = Ссылка.ПолучитьОбъект();
        Объект.Записать();
    Исключение
        УстановитьПривилегированныйРежим(Ложь);
        ВызватьИсключение;
    КонецПопытки;
    УстановитьПривилегированныйРежим(Ложь);
КонецПроцедуры
```

## Типичные ошибки

- Выдача роли «Полные права» всем пользователям вместо точной настройки.
- Проверка только интерфейса без проверки прав на сервере: пользователь может вызвать метод напрямую.
- Привилегированный режим, не снятый после операции или оставленный включённым.
- Попытка решить ограничение доступа к данным через интерфейс роли, а не через RLS.
- Дублирование ролей вместо использования профилей групп доступа.
- Проверка прав по имени роли вместо `ПравоДоступа`.
