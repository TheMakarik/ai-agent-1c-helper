# Тестирование и отладка

## Назначение

Скилл описывает отладку и тестирование решений на 1С: работу с отладчиком и точками останова, замер производительности кода и запросов, а также обзор автоматизации тестирования через Vanessa Automation.

## Ключевые понятия

- Отладчик — встроенный инструмент Конфигуратора для пошагового выполнения кода.
- Точка останова — место приостановки выполнения; бывает обычной, условной и на ошибке.
- Вычислить выражение — просмотр и вычисление переменных в момент остановки.
- Замер производительности — измерение длительности участка кода.
- Технологический журнал — журнал событий платформы для анализа производительности и ошибок.
- Vanessa Automation — инструмент автоматизации тестирования сценариев в стиле BDD.

## Как это работает

1. Отладка запускается клавишей F5 (Начать отладку); можно подключиться к активному пользователю.
2. Точка останова ставится клавишей F9 в модуле; условные точки настраиваются на срабатывание при выполнении условия.
3. При остановке доступны стек вызовов, значения переменных и вычисление выражений.
4. Производится замер участка: `ЗамерПроизводительности.НачатьЗамерВремени(Ключ)` и `ЗакончитьЗамерВремени(Ключ)`.
5. Результаты замеров и медленные запросы анализируются через технологический журнал и встроенный замер в отладчике.
6. Автотесты Vanessa Automation запускаются из `.feature`-файлов: сценарии на Gherkin, шаги на русском языке, наполнение через данные базы.

## Пример

```bsl
// Пример: замер длительности участка кода в миллисекундах.
Процедура ЗамеритьДлительность() Экспорт
    Ключ = "Расчёт цен документа";
    ЗамерПроизводительности.НачатьЗамерВремени(Ключ);

    // Измеряемый код.
    РассчитатьЦены();

    Длительность = ЗамерПроизводительности.ЗакончитьЗамерВремени(Ключ);
    Сообщить("Длительность, мс: " + Длительность);
КонецПроцедуры
```

Пример шага сценария Vanessa Automation:

```gherkin
Функционал: Проведение документа
    Сценарий: Проведение документа продажи
        Дано я открываю форму документа "Реализация товаров и услуг"
        Когда я записываю и провожу документ
        Тогда проведение документа прошло без ошибок
```

## Типичные ошибки

- Отладка на рабочей базе без согласования: остановки блокируют пользователей.
- Условные точки останова с побочными эффектами в условии.
- Оценка производительности «на глаз» вместо замера и технологического журнала.
- Замер без повторений: единичный прогон не отражает реальную нагрузку.
- Отладка только в файловой базе без проверки клиент-серверного варианта.
- Автотесты без подготовки данных: сценарии не воспроизводимы.
- Тесты, зависящие от текущей даты и настроек сеанса.
- Отсутствие регрессионных тестов после доработки расширением.
