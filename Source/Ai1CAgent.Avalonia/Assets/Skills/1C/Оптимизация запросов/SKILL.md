# Оптимизация запросов

## Назначение

Оптимизация запросов снижает время выполнения и нагрузку на СУБД. Она опирается на понимание плана выполнения, индексов, объёма данных и стоимости операций. Цель — получить нужные строки, не читая лишние таблицы и не выполняя избыточные соединения и агрегаты.

## Ключевые понятия

- План запроса — порядок соединений и чтения, доступен в технологическом журнале и через средства диагностики.
- Индекс — ускоряет отбор и соединение по индексированным полям (измерения регистров, ссылки, коды).
- `ОГРАНИЧИТЬ ТОП N` / `ПЕРВЫЕ N` — ограничение числа строк, полезно для предпросмотра и выборок.
- `ГДЕ` до группировки эффективнее `ИМЕЮЩИЕ` после.
- Раннее сужение данных: отбор на первом этапе уменьшает объём для соединений.
- Соединения виртуальных таблиц остатков по измерениям обычно индексированы.
- Селективность условия — доля отбираемых строк; узкие условия эффективнее.
- Отсутствие «полного сканирования» больших таблиц.

## Как это работает

СУБД выбирает план на основе статистики и условий. Если отбор идёт по неиндексированному полю составного типа, выполняется сканирование. Помогает явное приведение типа (`ВЫРАЗИТЬ`) и отбор по индексированным измерениям. Соединение больших таблиц дороже соединения «большая — маленькая», поэтому маленький набор полезно поместить во временную таблицу и индексировать.

Для проверки плана включают технологический журнал или отладку запросов и смотрят, сколько строк прочитано и сколько времени занял каждый этап. Оптимизируют по измерениям: сначала сокращают, потом соединяют, в конце сортируют. `ОГРАНИЧИТЬ ТОП` применяют вместе с `УПОРЯДОЧИТЬ`, чтобы получить именно N первых, а не произвольные строки.

## Пример

Ограничение выборки последних документов:

```bsl
ВЫБРАТЬ ПЕРВЫЕ 100
    Продажи.Ссылка КАК Документ,
    Продажи.Дата КАК Дата
ИЗ
    Документ.ПродажаТоваров КАК Продажи
ГДЕ
    Продажи.Проведен
УПОРЯДОЧИТЬ ПО
    Продажи.Дата УБЫВ
```

Сужение отбором до соединения:

```bsl
ВЫБРАТЬ
    Товары.Номенклатура КАК Номенклатура,
    СУММА(Товары.Сумма) КАК Сумма
ИЗ
    Документ.ПродажаТоваров.Товары КАК Товары
ГДЕ
    Товары.Ссылка.Дата МЕЖДУ &Начало И &Конец
    И Товары.Ссылка.Проведен
СГРУППИРОВАТЬ ПО
    Товары.Номенклатура
```

Проверка плана через замер времени:

```bsl
Начало = ТекущаяУниверсальнаяДатаВМиллисекундах();
Результат = Запрос.Выполнить();
ДлительностьМс = ТекущаяУниверсальнаяДатаВМиллисекундах() - Начало;
```

## Типичные ошибки

- Отбор по составному полю без `ВЫРАЗИТЬ` — потеря индекса и сканирование.
- Соединяют большие таблицы, не сузив их предварительно.
- Условие по сущности ставят в `ИМЕЮЩИЕ` вместо `ГДЕ` — лишняя работа.
- Используют `ОГРАНИЧИТЬ ТОП` без `УПОРЯДОЧИТЬ` и получают недетерминированный набор.
- Сравнивают дату целиком, забывая про индекс по `Период`.
- Считают агрегат по всей таблице там, где нужен итог за период.
- Оборачивают поле в функцию в условии (`ГОД(Дата) = …`) — индекс не используется, нужен диапазон дат.
