# Соединения в запросах

## Назначение

Соединения объединяют две таблицы по условию и позволяют получать связанные данные в одной выборке: документы с их товарами, справочники с остатками, проводки со счетами. Понимание вида соединения важно для правильного результата и производительности.

## Ключевые понятия

- `ВНУТРЕННЕЕ СОЕДИНЕНИЕ` — только строки, у которых есть соответствие в обеих таблицах.
- `ЛЕВОЕ СОЕДИНЕНИЕ` — все строки левой таблицы; справа при отсутствии соответствия `NULL`.
- `ПРАВОЕ СОЕДИНЕНИЕ` — все строки правой таблицы.
- `ПОЛНОЕ СОЕДИНЕНИЕ` — все строки обеих таблиц, непопарные — с `NULL` на другой стороне.
- `ЕСТЬNULL(Выражение, Значение)` — заменяет `NULL` на заданное значение.
- `ВЫРАЗИТЬ(Поле КАК Тип)` — приводит составное поле к конкретному типу.
- Тип соединения по умолчанию — внутреннее.
- Соединения с виртуальными таблицами остатков/оборотов по измерению.

## Как это работает

Условие соединения задаётся в `ПО` и может включать дополнительные фильтры правой таблицы. Условия по левой таблице лучше помещать в `ГДЕ`, а по правой — в `ПО` левого соединения, иначе левое соединение превращается во внутреннее: отбор в `ГДЕ` по правой таблице отбрасывает строки с `NULL`.

`ВЫРАЗИТЬ` нужен, когда поле имеет составной тип, а нужно обратиться к реквизитам конкретного типа. `ЕСТЬNULL` применяют, чтобы заменить отсутствующие значения (сумму необнаруженных остатков, наименование отсутствующего регистратора). Соединения дороги по стоимости, поэтому число источников стараются ограничивать.

## Пример

Внутреннее соединение справочника с табличной частью:

```bsl
ВЫБРАТЬ
    Номенклатура.Наименование КАК Товар,
    Цены.Цена КАК Цена
ИЗ
    Справочник.Номенклатура КАК Номенклатура
    ВНУТРЕННЕЕ СОЕДИНЕНИЕ РегистрСведений.ЦеныНоменклатуры КАК Цены
        ПО Номенклатура.Ссылка = Цены.Номенклатура
ГДЕ
    Цены.Период = &Дата
```

Левое соединение с заменой `NULL`:

```bsl
ВЫБРАТЬ
    Номенклатура.Наименование КАК Товар,
    ЕСТЬNULL(Остатки.КоличествоОстаток, 0) КАК Остаток
ИЗ
    Справочник.Номенклатура КАК Номенклатура
    ЛЕВОЕ СОЕДИНЕНИЕ РегистрНакопления.ТоварыНаСкладах.Остатки(
        &Момент, Склад = &Склад) КАК Остатки
        ПО Номенклатура.Ссылка = Остатки.Номенклатура
```

Приведение составного типа:

```bsl
ВЫБРАТЬ
    ВЫРАЗИТЬ(Движения.Регистратор КАК Документ.ПоступлениеТоваров).СуммаДокумента КАК Сумма
ИЗ
    РегистрНакопления.ТоварыНаСкладах КАК Движения
```

## Типичные ошибки

- Условие по правой таблице левого соединения ставят в `ГДЕ` — соединение становится внутренним.
- Пытаются сравнить `NULL` через `= NULL` — нужно `ЕСТЬNULL` или `ЕСТЬ NULL`.
- Обращаются к реквизиту составного поля без `ВЫРАЗИТЬ` — ошибка доступа.
- Соединяют таблицы без индексированных условий — медленный запрос.
- Используют `ПОЛНОЕ СОЕДИНЕНИЕ` там, где достаточно левого — лишние `NULL`-строки.
- Соединяют справочник-ссылку и таблицу объекта, ожидая оба реквизита в одной строке.
