# Ограничение доступа на уровне записей

## Назначение

Ограничение доступа на уровне записей (RLS, Row-Level Security) — механизм платформы, который показывает пользователю только те записи таблиц, которые разрешены его ролями. RLS применяется поверх прав на объект: право «Чтение» даёт доступ к таблице, а RLS ограничивает набор строк.

Скилл помогает настроить шаблоны ограничений и параметры сеанса и избегать типовых ошибок.

## Ключевые понятия

- Шаблон ограничения доступа — именованное условие на языке запросов, создаётся в роли.
- Условие на уровне записей — шаблон, назначенный конкретной таблице (объекту/регистру) в роли.
- Параметр сеанса — значение, доступное в условиях RLS; устанавливается через `УстановитьПараметрСеанса`.
- Пользовательские параметры — типовые параметры (`Пользователь`, `ТекущаяДата` и т. п.), доступные без установки.
- Привилегированный режим — выполнение кода в обход RLS и проверки прав.

## Как это работает

1. В роли создаётся шаблон, например `Организация В (&СписокОрганизаций)`.
2. Шаблон назначается таблице (справочнику, документу, регистру) в разделе «Ограничения доступа к данным».
3. Условие подставляется платформой в запросы пользователя к этой таблице.
4. Значения параметров задаются в коде: `УстановитьПараметрСеанса("СписокОрганизаций", Список)`, чаще при старте сеанса или при входе.
5. Для каждого пользователя/роли список разрешённых значений формируется по правилам конфигурации.

RLS действует и для итогов: итоги считаются по доступным записям. При изменении и удалении платформа проверяет, что запись доступна пользователю. Значения параметров сеанса можно устанавливать произвольно, если это позволяет логика; типовые параметры защищены от перезаписи.

## Пример

```bsl
// Пример: установка параметра сеанса, используемого в шаблоне RLS.
Процедура УстановитьОбластьДоступа(Пользователь) Экспорт
    // Список организаций, доступных пользователю, формируется по правилам БСП.
    СписокОрганизаций = Пользователи.ОрганизацииПользователя(Пользователь);
    Если СписокОрганизаций.Количество() = 0 Тогда
        УстановитьПараметрСеанса("СписокОрганизаций", Новый Массив);
    Иначе
        УстановитьПараметрСеанса("СписокОрганизаций", СписокОрганизаций);
    КонецЕсли;
КонецПроцедуры
```

Шаблон ограничения в роли для регистра:

```bsl
// Условие шаблона "ОграничениеПоОрганизациям"
ТоварыНаСкладах.Организация В (&СписокОрганизаций)
```

## Типичные ошибки

- Параметр сеанса не установлен — платформа выдаёт ошибку «Не установлено значение параметра» либо результат пуст.
- Установка параметра после начала выборки данных: часть запросов выполняется со старым значением.
- Отключение RLS привилегированным режимом в пользовательских сценариях.
- Шаблон с ошибкой в языке запросов: неверное имя поля или отсутствующая таблица.
- Ограничение назначается на таблицу, но не покрывает связанные таблицы, из которых строятся отчёты.
- Слишком сложные условия RLS дают заметную нагрузку на запросы.
- Попытка решить доступ к отдельным записям интерфейсом роли вместо RLS.
