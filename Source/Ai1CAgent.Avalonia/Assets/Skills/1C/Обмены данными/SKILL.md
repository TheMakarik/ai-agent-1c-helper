# Обмены данными

## Назначение

Скилл описывает организацию обмена между информационными базами и системами: планы обмена и узлы, автоматическую и ручную регистрацию изменений, выгрузку и загрузку сообщений, XML-сериализацию объектов и типовые сценарии синхронизации.

## Ключевые понятия

- План обмена — объект метаданных, описывающий состав узлов и состав выгружаемых данных.
- Узел обмена — запись плана обмена, ссылка на конкретную сторону обмена.
- Регистрация изменений — фиксация изменённых объектов для конкретных узлов; ведётся в таблице плана обмена.
- Выгрузка/загрузка изменений — менеджер плана обмена предоставляет методы формирования и приёма сообщения.
- Сериализатор XDTO — штатный способ превратить объект в XML и обратно.
- Правила обмена / менеджер обмена — типовой механизм конвертации между разными структурами (БСП, «Конвертация данных»).

## Как это работает

1. Создаётся план обмена с нужными объектами (состав данных).
2. Определяются узлы; один из них — текущий узел базы.
3. При записи объектов платформа автоматически регистрирует изменения для узлов (если включена авторегистрация); при необходимости регистрация выполняется вручную.
4. Узел выгружает накопленные изменения в сообщение (файл или поток).
5. Принимающая сторона загружает сообщение и применяет изменения к своим объектам.
6. После подтверждения изменения для узла снимаются, чтобы не выгружать их повторно.

## Пример

```bsl
// Пример: XML-сериализация объекта обмена в файл через XDTO.
Процедура ВыгрузитьОбъектВXML(Объект, ПутьКФайлу) Экспорт
    Сериализатор = Новый СериализаторXDTO(ФабрикаXDTO);
    ЗаписьXML = Новый ЗаписьXML;
    ЗаписьXML.ОткрытьФайл(ПутьКФайлу);
    Сериализатор.ЗаписатьXML(ЗаписьXML, Объект);
    ЗаписьXML.Закрыть();
КонецПроцедуры

// Пример: чтение объекта из XML обратно.
Функция ЗагрузитьОбъектИзXML(ПутьКФайлу)
    ЧтениеXML = Новый ЧтениеXML;
    ЧтениеXML.ОткрытьФайл(ПутьКФайлу);
    Сериализатор = Новый СериализаторXDTO(ФабрикаXDTO);
    Возврат Сериализатор.ПрочитатьXML(ЧтениеXML);
КонецФункции
```

## Типичные ошибки

- Авторегистрация выключена, а ручная не реализована: часть изменений не попадает в выгрузку.
- Изменения не снимаются после подтверждения и выгружаются бесконечно.
- Конфликт изменений одного объекта на разных узлах без правил разрешения.
- Ссылки на объекты, отсутствующие на принимающей стороне: нужен поиск/сопоставление по ключу.
- Большие сообщения формируются в памяти вместо потоковой обработки.
- Сериализация объектов с незаполненными обязательными реквизитами XDTO-типов.
- Отсутствие мониторинга очередей обмена и журнала ошибок загрузки.
