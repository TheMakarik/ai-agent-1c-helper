# Система компоновки данных

## Назначение

Система компоновки данных (СКД) строит отчёты из декларативного описания: разработчик задаёт схему и наборы данных, а платформа сама формирует запросы, группировки и вывод. Пользователь настраивает отчёт без изменения кода. СКД применяется в отчётах и динамических списках.

## Ключевые понятия

- Схема компоновки данных — корневой объект: наборы данных, связи, параметры, вычисляемые поля, настройки.
- Набор данных «Запрос» — текст запроса, поля и параметры которого описываются в схеме.
- Набор данных «Объект» — данные из кода (таблица значений, дерево), передаваемые в компоновщик.
- Связь наборов — соединение двух наборов по выражению, с указанием типа (левый, внутренний).
- Параметры — входные значения, в том числе выражаемые пользователем; `&Период`.
- Вычисляемые поля — выражения поверх полей наборов.
- Настройки — группировки, отборы, порядок и условное оформление, задаваемые из схемы или пользователем.
- Расшифровка — переход от строки отчёта к детализирующим данным.

## Как это работает

Компоновщик берёт схему и настройки, формирует и выполняет запросы, соединяет наборы и агрегирует результат по группировкам. Поля одного набора доступны в связях и вычисляемых полях по имени. Пользовательские настройки переопределяют заданные в схеме. Для отчёта в коде создаётся `Отчёт.СкомпоноватьРезультат`, результат выводится в табличный документ.

Набор «Объект» полезен, когда данные уже получены кодом; набор «Запрос» — когда источник в базе. Связь наборов должна идти по выражению с одинаковым типом, иначе соединение не сработает. Параметры схемы должны быть установлены до компоновки, а необязательные — иметь значение по умолчанию.

## Пример

Набор данных с запросом и параметром:

```bsl
// Текст запроса набора данных "Продажи" в схеме СКД
ВЫБРАТЬ
    Продажи.Менеджер КАК Менеджер,
    Продажи.Номенклатура КАК Номенклатура,
    Продажи.Количество КАК Количество,
    Продажи.Сумма КАК Сумма
ИЗ
    Документ.ПродажаТоваров.Товары КАК Продажи
ГДЕ
    Продажи.Ссылка.Дата МЕЖДУ &НачалоПериода И &КонецПериода
```

Компоновка результата в коде отчёта:

```bsl
Схема = Отчеты.Продажи.ПолучитьМакет("ОсновнаяСхемаКомпоновкиДанных");
Настройки = Схема.НастройкиПоУмолчанию;

Компоновщик = Новый КомпоновщикНастроекКомпоновкиДанных;
Компоновщик.Инициализировать(Схема, Настройки);
Компоновщик.Настройки.ПараметрыДанных.УстановитьЗначениеПараметра(
    "НачалоПериода", НачалоМесяца(ТекущаяДата()));
Компоновщик.Настройки.ПараметрыДанных.УстановитьЗначениеПараметра(
    "КонецПериода", КонецМесяца(ТекущаяДата()));

КомпоновщикМакета = Новый КомпоновщикМакетаКомпоновкиДанных;
МакетКомпоновки = КомпоновщикМакета.Выполнить(Схема, Компоновщик.ПолучитьНастройки());
ВнешниеНаборы = Новый Структура;

Процессор = Новый ПроцессорКомпоновкиДанных;
Процессор.Инициализировать(МакетКомпоновки, ВнешниеНаборы);
Результат = Новый ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент;
Результат.Вывести(Процессор);
```

## Типичные ошибки

- Соединяют наборы по выражениям разных типов — связь не работает.
- Обращаются к полю набора «Объект» в запросе — таких полей в запросе нет.
- Не задают необязательный параметр, и компоновка падает на пустом значении.
- Переопределяют настройки напрямую в схеме вместо пользовательских настроек.
- Ожидают детализацию там, где не настроена расшифровка.
- Дублируют вычисляемые поля, которые уже есть в наборе данных.
